# 安全加固指南

> 本文档提供 EnterpriseKB 的安全加固清单，覆盖认证、权限、加密、审计与检查项，适用于生产环境部署。

## 1. 安全原则

- 最小权限：组件与账户仅授予必要权限
- 纵深防御：多层安全控制，单点失陷不致全局沦陷
- 默认安全：开箱即用即为安全配置
- 可审计：所有敏感操作留痕

## 2. 认证配置

### 2.1 密码策略

```yaml
security:
  password_min_length: 12
  password_require_uppercase: true
  password_require_symbol: true
  password_expire_days: 90
  password_history: 5          # 不能复用最近5次密码
  max_login_attempts: 5        # 连续失败锁定
  lockout_minutes: 15
```

### 2.2 多因素认证（MFA）

- 管理员账户强制启用 MFA（TOTP）
- 支持对接企业 SSO（OIDC / SAML）
- 敏感操作（删除文档、导出数据）需二次验证

### 2.3 会话管理

- JWT 有效期不超过 2 小时
- Refresh Token 7 天，且支持吊销
- 登出时将 Token 加入黑名单（Redis）
- 同一账户并发会话数限制为 3

## 3. 权限设置

### 3.1 角色模型

| 角色 | 权限范围 |
| --- | --- |
| super_admin | 全局管理 |
| tenant_admin | 本租户管理、用户管理 |
| editor | 文档上传、编辑、删除 |
| viewer | 仅检索与查看 |
| api_client | API 调用（按 scope 限制） |

### 3.2 RBAC 配置示例

```python
permissions = {
    "editor": ["doc:read", "doc:create", "doc:delete", "retrieve:use"],
    "viewer": ["doc:read", "retrieve:use"],
}
```

### 3.3 行级权限

基于 PostgreSQL RLS 实现租户隔离，详见《多租户架构说明》。文档级权限通过 `metadata.acl` 字段控制可见性。

## 4. 数据加密

### 4.1 传输加密

- 全站强制 HTTPS（TLS 1.2+）
- 内部服务间通信启用 mTLS
- 数据库连接强制 SSL

### 4.2 静态加密

| 数据 | 加密方式 |
| --- | --- |
| 数据库整库 | 磁盘级加密（LUKS） |
| 敏感字段 | 应用层 AES-256-GCM |
| 对象存储 | 服务端加密 SSE-S3 |
| 备份文件 | GPG 加密后上传 |

### 4.3 密钥管理

- 主密钥托管于 HashiCorp Vault，禁止硬编码
- 密钥定期轮换（90 天）
- 数据库加密密钥与业务密钥分离

## 5. 审计日志

### 5.1 审计范围

记录以下操作的完整日志：

- 用户登录/登出、权限变更
- 文档上传/删除/导出
- 检索与问答请求（脱敏后）
- 配置修改
- 管理员操作

### 5.2 日志格式

```json
{
  "timestamp": "2026-07-30T10:23:11Z",
  "actor": "user_88",
  "action": "document.delete",
  "resource": "doc_123",
  "tenant_id": "tenant_001",
  "source_ip": "10.0.1.5",
  "result": "success",
  "request_id": "req_ab12"
}
```

### 5.3 日志保护

- 审计日志写入只追加存储，防篡改
- 保留至少 180 天，重要操作 1 年
- 定期归档到 WORM（一写多读）存储

## 6. 网络安全

- 数据库/Redis 仅监听内网，禁止公网暴露
- 使用安全组限定来源 IP
- API 网关配置 WAF 规则（防 SQL 注入、XSS）
- 出站流量通过代理白名单控制

## 7. 依赖与供应链安全

- 定期执行 `pip-audit` / `npm audit` 扫描漏洞
- 锁定依赖版本（lockfile）
- 镜像基于最小化基础镜像并定期重建
- CI 集成 Trivy 镜像扫描

## 8. 安全检查清单

部署前逐项确认：

- [ ] 所有默认密码已修改
- [ ] JWT_SECRET 与加密密钥已使用强随机值
- [ ] HTTPS 证书有效且自动续期
- [ ] 数据库端口未对公网开放
- [ ] 管理后台已启用 MFA
- [ ] 审计日志已开启并能正常写入
- [ ] 定期备份已配置并验证可恢复
- [ ] 依赖漏洞扫描无高危项
- [ ] 限流与防爆破已启用
- [ ] 敏感信息未硬编码于代码或镜像

## 9. 漏洞响应流程

1. **发现**：内部发现或外部上报
2. **评估**：定级（CVSS）与影响范围
3. **止血**：紧急补丁或临时缓解
4. **修复**：开发正式修复并测试
5. **发布**：发布安全版本与公告
6. **复盘**：更新加固指南与检查清单

## 10. 合规与隐私

- 支持 GDPR / 个保法的数据删除请求
- 个人数据最小化采集
- 数据驻留可按租户配置区域

> 安全是持续的过程，建议每季度执行一次安全自查与渗透测试。
