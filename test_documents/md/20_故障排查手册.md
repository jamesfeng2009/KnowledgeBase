# 故障排查手册

> 本手册汇总 EnterpriseKB 常见故障的分类、排查步骤、诊断命令、修复方案与预防措施，供运维与 On-call 人员参考。

## 1. 故障分类

| 类别 | 典型现象 | 严重度 |
| --- | --- | --- |
| 服务可用性 | API 不可访问、502/503 | P0 |
| 检索质量 | 召回为空、答非所问 | P1 |
| 性能问题 | 响应缓慢、超时 | P1 |
| 数据问题 | 文档丢失、索引失败 | P1 |
| 鉴权问题 | 登录失败、越权 | P0/P1 |
| 依赖故障 | 数据库/Redis/LLM 不可用 | P0 |

## 2. 通用排查方法论

1. **确认范围**：全量还是单租户？影响哪些接口？
2. **查看监控**：Dashboard 是否有异常拐点
3. **查看日志**：按时间与 request_id 过滤错误日志
4. **链路追踪**：Jaeger 定位慢节点
5. **最小复现**：尝试稳定复现问题
6. **止血优先**：先恢复服务，再根因分析
7. **记录复盘**：故障后编写复盘文档

## 3. 服务不可用

### 3.1 现象：API 返回 502/503

**排查步骤**：

```bash
# 1. 检查容器/进程状态
docker compose ps
# 或
systemctl status ekb-api

# 2. 检查端口监听
ss -tlnp | grep 8000

# 3. 查看应用日志
docker compose logs --tail=200 ekb-api

# 4. 检查健康端点
curl http://localhost:8000/health
```

**常见原因与修复**：

| 原因 | 修复 |
| --- | --- |
| 进程崩溃/OOM | 查看内存限制，增大后重启 |
| 依赖未就绪 | 检查 postgres/redis 连通性 |
| 配置错误 | `ekb config show` 核对配置 |
| 端口冲突 | 修改监听端口 |

### 3.2 现象：全部接口超时

```bash
# 检查数据库连接池是否耗尽
docker compose exec postgres psql -U ekb -c \
  "SELECT count(*) FROM pg_stat_activity WHERE state='active';"

# 检查 Redis
docker compose exec redis redis-cli info clients
```

若连接耗尽，临时重启 API 释放连接，再排查连接泄漏。

## 4. 检索质量问题

### 4.1 现象：检索结果为空

**诊断命令**：

```bash
# 检查文档是否已索引
ekb doc status --id doc_123

# 检查向量索引是否存在
docker compose exec postgres psql -U ekb -c \
  "SELECT indexname FROM pg_indexes WHERE tablename='document_chunks';"

# 直接执行向量查询验证
ekb debug retrieve --query "测试" --explain
```

**可能原因**：

- 文档未完成索引（状态 pending/failed）-> 重新索引
- 向量索引未建立 -> 创建 HNSW 索引
- `score_threshold` 过高 -> 调低阈值
- 租户/权限过滤导致无可见文档 -> 检查 ACL

### 4.2 现象：答非所问/幻觉

- 检查 Prompt 模板是否正确加载
- 检查检索 top_k 是否过少
- 查看实际传入 LLM 的 context（开启 debug 日志）
- 评估是否需要重排序或查询改写

## 5. 性能问题

### 5.1 检索慢

```bash
# 开启慢查询日志
ekb config set db.slow_query_log 1000  # 超过1秒记录

# 查看执行计划
docker compose exec postgres psql -U ekb -c \
  "EXPLAIN ANALYZE SELECT id FROM document_chunks ORDER BY embedding <=> '[...]' LIMIT 5;"
```

**优化方向**：

- 确认命中 HNSW 索引（非 Seq Scan）
- 调整 `ef_search`
- 检查是否需重建索引（碎片化）
- 大表考虑分片

### 5.2 文档解析慢/队列堆积

```bash
# 查看 Worker 状态
ekb worker status

# 查看待处理任务
docker compose exec redis redis-cli llen ekb_tasks
```

**处理**：增加 Worker 实例、提高并发数、关闭非必要 OCR。

## 6. 依赖故障

### 6.1 数据库故障

```bash
# 连通性
docker compose exec postgres pg_isready

# 主从状态（若启用复制）
docker compose exec postgres psql -U ekb -c "SELECT * FROM pg_stat_replication;"

# 锁等待
docker compose exec postgres psql -U ekb -c \
  "SELECT * FROM pg_stat_activity WHERE wait_event_type IS NOT NULL;"
```

数据库不可用时，API 应降级返回只读提示，避免雪崩。

### 6.2 Redis 故障

```bash
docker compose exec redis redis-cli ping
docker compose exec redis redis-cli info memory
```

Redis 不可用会导致缓存失效与任务队列停滞，优先恢复 Redis。

### 6.3 LLM 服务故障

- 检查到模型服务的网络连通性
- 查看是否触发限流（429）
- 启用 `fallback_model` 降级
- 极端情况下返回"模型暂不可用"提示

## 7. 数据问题

### 7.1 文档索引失败

```bash
# 查看失败原因
ekb doc list --status failed --limit 20

# 查看具体错误
ekb doc logs --id doc_123
```

常见原因：文件损坏、格式不支持、Embedding API 超时。修复后批量重试：

```bash
ekb doc reindex --status failed --limit 100
```

### 7.2 数据不一致

- 文档已删但分块残留：`ekb index cleanup --force`
- 向量维度不一致：检查 Embedding 配置，重建索引

## 8. 鉴权问题

### 8.1 登录失败

- 检查用户状态是否 disabled
- 检查密码是否过期
- 查看 `max_login_attempts` 是否触发锁定

### 8.2 越权访问

若怀疑越权：

```sql
-- 检查 RLS 是否启用
SELECT relname, relrowsecurity FROM pg_class WHERE relname='documents';

-- 检查策略
SELECT * FROM pg_policies WHERE tablename='documents';
```

> RLS 策略缺失是严重安全事件，需立即修复并审计历史访问。

## 9. 诊断工具速查

| 工具/命令 | 用途 |
| --- | --- |
| `ekb health` | 一键健康检查 |
| `ekb debug retrieve --explain` | 检索链路诊断 |
| `ekb config show` | 查看生效配置 |
| `docker compose logs -f` | 实时日志 |
| `ekb worker status` | Worker 状态 |
| `pg_stat_activity` | 数据库活动会话 |
| Jaeger UI | 链路追踪 |

## 10. 修复方案与预防

### 10.1 止血手段优先级

1. 重启异常实例
2. 降级非核心功能
3. 限流保护核心链路
4. 切换备用依赖（如备用 LLM）

### 10.2 预防措施

- 完善监控告警，提前发现
- 定期故障演练（混沌工程）
- 关键依赖配置自动故障转移
- 保持回滚方案随时可用
- 每次故障后更新本手册与 Runbook

## 11. 故障复盘模板

```markdown
## 故障概述
- 时间：
- 影响：
- 严重度：

## 时间线
- 00:00 告警触发
- 00:05 开始响应
- 00:30 止血恢复

## 根因分析
（详细原因）

## 改进措施
- [ ] 监控补充
- [ ] 代码修复
- [ ] 流程优化
```

> 排查时保持冷静，先止血后根因，所有操作记录时间线便于复盘。
