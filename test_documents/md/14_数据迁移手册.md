# 数据迁移手册

> 本手册指导 EnterpriseKB 在不同环境（开发->测试->生产）、不同版本（1.x->2.x）、不同存储间的数据迁移操作。

## 1. 迁移场景分类

| 场景 | 风险 | 停机要求 |
| --- | --- | --- |
| 环境间迁移 | 中 | 视数据量 |
| 版本升级迁移 | 高 | 需维护窗口 |
| 存储迁移（如换库） | 高 | 需停机 |
| 租户拆分/合并 | 高 | 需停机 |

## 2. 迁移前检查清单

- [ ] 确认源端与目标端版本兼容性
- [ ] 完整备份源数据（数据库 + 对象存储）
- [ ] 评估数据量与预估耗时
- [ ] 通知相关业务方停机窗口
- [ ] 准备回滚方案并演练
- [ ] 确认目标端容量充足
- [ ] 检查目标端扩展（pgvector 等）已安装

## 3. 环境间迁移

### 3.1 导出源环境数据

```bash
# 导出指定租户
ekb tenant export --id tenant_001 --out /backup/tenant_001.zip

# 或全量导出
ekb system export --out /backup/full.zip
```

导出包包含：文档元数据、分块与向量、配置、权限。

### 3.2 导入目标环境

```bash
ekb system import --in /backup/tenant_001.zip \
  --tenant-map tenant_001:tenant_002 \
  --conflict-skip
```

`--tenant-map` 可在导入时重映射租户 ID。

## 4. 版本升级迁移（1.x -> 2.x）

### 4.1 迁移脚本说明

2.0 提供专用迁移工具 `ekb migrate-from-v1`，处理：

- 表结构重构映射
- 向量格式转换（旧维度 -> 新维度需重新 Embedding）
- 配置文件格式转换（.env -> yaml）
- 权限模型迁移

### 4.2 执行步骤

```bash
# 1. 停止旧服务
systemctl stop ekb-v1

# 2. 备份
pg_dump -Fc ekb_v1 > ekb_v1.dump

# 3. 部署 v2 空实例
docker compose up -d postgres redis

# 4. 执行迁移
ekb migrate-from-v1 \
  --source-db "postgresql://user:pwd@oldhost/ekb_v1" \
  --reembed       # 维度变化时需重新向量化
  --dry-run       # 先试运行

# 5. 校验后正式执行（去掉 --dry-run）
```

### 4.3 重新向量化注意事项

若 Embedding 模型变化导致维度不同，必须重新生成向量。此过程耗时长，建议：

- 分批处理，优先迁移高频文档
- 监控 Embedding API 限流
- 迁移期间新文档入库使用新模型

## 5. 数据库存储迁移

### 5.1 逻辑迁移（pg_dump）

适用于中小数据量或跨版本：

```bash
pg_dump -U ekb -Fc -f ekb.dump enterprise_kb
# 传输到新库
pg_restore -U ekb -d enterprise_kb -j 4 ekb.dump
```

### 5.2 物理迁移（pg_basebackup）

适用于大库、同版本：

```bash
pg_basebackup -h oldhost -U replicator -D /var/lib/postgresql/data -X stream -P
```

### 5.3 在线迁移（逻辑复制）

零停机方案，配置发布订阅：

```sql
-- 源库
CREATE PUBLICATION ekb_pub FOR ALL TABLES;

-- 目标库
CREATE SUBSCRIPTION ekb_sub
  CONNECTION 'host=oldhost user=replicator'
  PUBLICATION ekb_pub;
```

## 6. 对象存储迁移

使用 `rclone` 在 MinIO/S3 间同步：

```bash
rclone sync old-minio:ekb-docs new-minio:ekb-docs \
  --transfers 16 --checkers 8 --progress
```

迁移后更新 `storage.endpoint` 配置并验证文档可访问。

## 7. 数据校验

### 7.1 计数校验

```bash
ekb verify --source old --target new --check count,checksum
```

| 校验项 | 方法 |
| --- | --- |
| 文档数 | 对比两端 count |
| 分块数 | 对比 count |
| 向量抽样 | 随机抽样比对哈希 |
| 文件完整性 | 对比 OSS 对象 ETag |

### 7.2 业务校验

- 抽检若干文档能否正常检索
- 验证权限是否生效
- 检查审计日志连续性

## 8. 回滚方案

### 8.1 回滚条件

- 数据校验失败
- 关键功能不可用
- 业务方确认不可接受

### 8.2 回滚步骤

1. 停止目标端服务
2. 恢复源端备份（若有修改）
3. 切换 DNS/配置指回源端
4. 启动源端服务
5. 通知业务方恢复

```bash
# 恢复源库备份
pg_restore -U ekb -d enterprise_kb -c ekb_pre_migration.dump
```

## 9. 迁移后收尾

- 更新监控告警指向新环境
- 旧环境保留观察 7 天后下线
- 归档迁移记录与校验报告
- 更新架构文档中的环境拓扑

## 10. 常见问题

- **迁移中断如何续传**：`ekb migrate-from-v1 --resume` 从断点继续
- **字符集不一致**：确保两端均为 UTF-8，必要时用 `iconv` 转换
- **外键约束冲突**：导入时加 `--disable-triggers` 或按依赖顺序

> 任何迁移操作都必须「先备份、先试运行、先校验」，宁慢勿错。
