# 数据库设计文档

> 本文档描述 EnterpriseKB 的数据库表结构、索引设计、迁移管理与实体关系。

## 1. 数据库概述

- 数据库：PostgreSQL 16
- 扩展：pgvector（向量存储）、pg_trgm（模糊匹配）、uuid-ossp
- 字符集：UTF-8
- 时区：所有时间字段统一存储 UTC，展示层转换

## 2. 表结构设计

## 3. 索引设计

### 3.1 向量索引

```sql
CREATE INDEX idx_chunks_embedding
ON document_chunks
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);
```

### 3.2 业务索引

```sql
-- 租户维度查询
CREATE INDEX idx_documents_tenant ON documents(tenant_id, created_at DESC);
CREATE INDEX idx_chunks_doc ON document_chunks(doc_id);

-- 全文检索
CREATE INDEX idx_chunks_content_fts
ON document_chunks
USING gin (to_tsvector('simple', content));

-- JSONB 元数据查询
CREATE INDEX idx_documents_meta ON documents USING gin (metadata jsonb_path_ops);
```

### 3.3 索引设计原则

1. 高频查询字段建组合索引，遵循最左前缀
2. 向量索引优先 HNSW，兼顾召回率与延迟
3. 写多读少的日志表避免过度索引
4. 定期使用 `pg_stat_user_indexes` 清理未使用索引

## 4. ER 关系说明

```
tenants 1───* users
tenants 1───* documents
documents 1───* document_chunks
users 1───* documents (created_by)
users 1───* query_logs
```

- 租户与用户、文档为一对多
- 文档与分块为一对多
- 分块表冗余 `tenant_id` 以支持行级安全策略

## 5. 迁移管理

使用 Alembic 进行版本化迁移。

### 5.1 创建迁移

```bash
ekb db revision -m "add query_logs table"
```

### 5.2 迁移文件示例

```python
def upgrade():
    op.create_table(
        "query_logs",
        sa.Column("id", sa.BigInteger, primary_key=True),
        sa.Column("tenant_id", sa.dialects.postgresql.UUID),
        sa.Column("query", sa.Text),
        sa.Column("latency_ms", sa.Integer),
        sa.Column("created_at", sa.DateTime(timezone=True)),
    )
    op.create_index("idx_logs_tenant_time", "query_logs", ["tenant_id", "created_at"])

def downgrade():
    op.drop_table("query_logs")
```

### 5.3 执行与回滚

```bash
ekb db upgrade head      # 升级到最新
ekb db downgrade -1      # 回退一个版本
ekb db history           # 查看迁移历史
```

## 6. 数据归档与清理

- `query_logs` 保留 90 天，超期归档到冷存储
- 已删除文档的分块通过级联或定时任务清理
- 向量表膨胀时执行 `VACUUM (FULL, ANALYZE) document_chunks;`

## 7. 备份与恢复

```bash
# 全量逻辑备份
pg_dump -U ekb -Fc enterprise_kb > ekb.dump

# 恢复
pg_restore -U ekb -d enterprise_kb ekb.dump
```

建议结合 WAL 归档实现时间点恢复（PITR）。

> 生产环境修改表结构必须先在 staging 验证，并通过迁移评审。
