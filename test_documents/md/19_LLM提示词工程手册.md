# LLM 提示词工程手册

> 本手册系统介绍 EnterpriseKB 中 RAG 问答的提示词（Prompt）结构、模板设计、变量替换、效果评估与常见模式。

## 1. Prompt 在 RAG 中的作用

在检索增强生成中，Prompt 决定了 LLM 如何利用检索到的上下文生成回答。优秀的 Prompt 能：

- 提升回答准确性与忠实度（减少幻觉）
- 规范输出格式，便于下游解析
- 控制风格与语气
- 显式引用来源，增强可信度

## 2. Prompt 结构设计

EnterpriseKB 的问答 Prompt 采用「角色 + 指令 + 上下文 + 约束 + 输出格式」五段式结构：

```
[角色定义]
[任务指令]
[检索上下文]
[约束规则]
[输出格式]
```

### 2.1 基础模板示例

```
你是企业知识库助手，只能基于提供的参考资料回答问题。

【参考资料】
{context}

【用户问题】
{question}

【规则】
1. 答案必须来自参考资料，不得编造
2. 若资料不足，回答"根据现有资料无法回答"
3. 在关键信息后标注来源编号，如 [1]
4. 语言简洁，分点陈述

【输出格式】
先给出直接回答，再列出引用来源。
```

## 3. 模板设计

### 3.1 模板变量

| 变量 | 说明 | 来源 |
| --- | --- | --- |
| {context} | 检索片段拼接 | 检索引擎 |
| {question} | 用户问题 | 用户输入 |
| {history} | 对话历史 | 会话存储 |
| {persona} | 角色设定 | 场景配置 |
| {language} | 输出语言 | 租户配置 |

### 3.2 多轮对话模板

```
【对话历史】
{history}

【最新参考资料】
{context}

【当前问题】
{question}

请结合历史对话与参考资料作答。
```

### 3.3 带工具调用的模板

当检索不足以回答时，引导 LLM 调用工具：

```
你可调用以下工具补充信息：
- search_intranet(query): 搜索内网
- query_hr_db(condition): 查询人事数据

若参考资料已足够，直接回答；否则说明需要调用哪个工具及参数。
```

## 4. 变量替换机制

### 4.1 替换实现

使用安全的模板引擎（Jinja2）避免注入：

```python
from jinja2 import Template

template = Template(PROMPT_TPL)
prompt = template.render(
    context=formatted_context,
    question=user_question,
    history=dialog_history,
)
```

### 4.2 上下文格式化

检索片段按统一格式拼接，含来源编号：

```python
def format_context(chunks):
    parts = []
    for i, c in enumerate(chunks, 1):
        parts.append(f"[{i}] 来源: {c.title}\n{c.content}")
    return "\n\n".join(parts)
```

### 4.3 长度控制

- 统计各片段 token 数，按相关性得分截断
- 预留模型 max_tokens 给生成部分
- 超长时优先保留高分片段

## 5. 效果评估

### 5.1 评估维度

| 维度 | 含义 | 评估方法 |
| --- | --- | --- |
| 忠实度 Faithfulness | 回答是否可被上下文支持 | LLM 评判 + 人工抽检 |
| 相关性 Relevance | 回答是否切题 | 标注对比 |
| 引用准确率 | 引用编号与内容对应 | 自动校验 |
| 拒答合理性 | 资料不足时是否正确拒答 | 评测集统计 |

### 5.2 评测流程

1. 维护评测集（问题 + 参考答案 + 是否应拒答）
2. 用候选 Prompt 跑全量评测
3. 用 LLM-as-Judge 自动打分 + 人工复核
4. 与基线 Prompt 对比，择优上线

### 5.3 评估脚本

```bash
ekb prompt eval \
  --template prompts/v2.txt \
  --dataset eval/rag_benchmark.jsonl \
  --metrics faithfulness,relevance,citation
```

## 6. 常见 Prompt 模式

### 6.1 思维链（CoT）

要求模型分步推理，适合复杂问题：

```
请先逐步分析问题，再给出最终答案。
分析过程：
1. ...
2. ...
最终答案：
```

### 6.2 少样本（Few-shot）

提供示例引导格式：

```
示例1：
问题：年假几天？
回答：根据资料，入职满1年享5天年假 [1]。

现在请回答：
问题：{question}
回答：
```

### 6.3 自我校验

让模型自检回答是否有依据：

```
回答后请自检：每个陈述是否都能在参考资料中找到对应？若不能，请修正或标注。
```

### 6.4 拒答引导

明确拒答条件，降低幻觉：

```
若参考资料未涉及该问题，必须回答："现有资料无法回答该问题"，不得推测。
```

## 7. Prompt 版本管理

- 模板文件纳入 Git，按版本命名（`prompts/v2.txt`）
- 线上 Prompt 与评测结果绑定记录
- 变更需走评测对比，指标不退步方可上线
- 支持灰度：按租户/比例切换 Prompt 版本

## 8. 常见问题与对策

| 问题 | 对策 |
| --- | --- |
| 模型编造来源 | 强化拒答约束 + 引用校验 |
| 回答冗长 | 增加"不超过N句"约束 |
| 格式不稳定 | Few-shot 示例 + 严格格式说明 |
| 多轮上下文丢失 | 显式注入历史 + 摘要压缩 |
| 中英文混杂 | 指定输出语言变量 |

## 9. 安全与成本

- Prompt 注入防护：用户输入与指令分离，明确边界
- 敏感信息脱敏后再进入 Prompt
- 控制 context 长度降低 token 成本
- 简单问题用短 Prompt，复杂问题用完整 Prompt（路由策略）

## 10. 最佳实践总结

- 结构化分段，角色与约束清晰
- 强制引用与拒答，抑制幻觉
- 用评测集量化迭代，避免凭感觉调优
- 版本化与灰度，确保变更可控

> Prompt 工程是经验与数据驱动的结合，持续评测比一次性优化更重要。
