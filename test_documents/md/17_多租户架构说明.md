# 多租户架构说明

> 本文档阐述 EnterpriseKB 多租户隔离模型、行级安全策略、权限模型与运维注意事项。

## 1. 多租户模型选型

EnterpriseKB 采用「共享数据库 + 行级隔离（RLS）」模型，平衡隔离性与运维成本。

### 1.1 三种模型对比

| 模型 | 隔离强度 | 运维成本 | 扩展性 | 适用 |
| --- | --- | --- | --- | --- |
| 共享数据库+RLS | 中 | 低 | 高 | 中小租户多 |
| 独立 Schema | 较高 | 中 | 中 | 中型租户 |
| 独立数据库 | 高 | 高 | 低 | 大客户/合规 |

### 1.2 选型理由

- 企业内部知识库租户数多但单租户数据量中等
- RLS 在数据库层强制隔离，应用层 bug 难以越权
- 运维只需维护单库，备份与监控简单

## 2. 行级安全（RLS）策略

### 2.1 启用 RLS

```sql
ALTER TABLE documents ENABLE ROW LEVEL SECURITY;
ALTER TABLE document_chunks ENABLE ROW LEVEL SECURITY;
ALTER TABLE query_logs ENABLE ROW LEVEL SECURITY;
```

### 2.2 策略定义

每个租户表都含 `tenant_id` 字段，策略基于会话变量强制过滤：

```sql
CREATE POLICY tenant_isolation ON documents
  USING (tenant_id = current_setting('app.tenant_id')::uuid);

CREATE POLICY tenant_isolation ON document_chunks
  USING (tenant_id = current_setting('app.tenant_id')::uuid);
```

### 2.3 会话上下文设置

应用每次获取连接后设置租户上下文：

```python
async with db.acquire() as conn:
    await conn.execute(f"SET LOCAL app.tenant_id = '{tenant_id}'")
    # 后续所有查询自动受限
    docs = await conn.fetch("SELECT * FROM documents")
```

### 2.4 强制与绕过控制

- 业务账户不授予 `BYPASSRLS`，确保策略生效
- 仅运维超管账户可绕过（用于跨租户维护）
- 定期审计是否存在遗漏 RLS 的表

## 3. 权限模型

### 3.1 租户内角色

```
tenant_admin ─┬─ editor ─── viewer
              └─ api_client
```

- `tenant_admin`：本租户用户管理、配额管理
- `editor`：文档增删改、检索
- `viewer`：只读检索
- `api_client`：API 调用，按 scope 限制

### 3.2 文档级 ACL

文档 `metadata.acl` 控制细粒度可见性：

```json
{
  "acl": {
    "allow_groups": ["finance", "hr"],
    "deny_users": ["user_99"],
    "allow_users": ["user_88"]
  }
}
```

检索引擎在召回阶段结合 ACL 过滤，确保不越权返回。

## 3.3 跨租户隔离要点

- 缓存键必须含 `tenant_id`，防止租户间缓存串读
- 向量索引查询条件始终带 `tenant_id` 过滤
- 文件存储路径按租户分桶：`oss://ekb/{tenant_id}/...`

## 4. 配额管理

| 资源 | 默认配额 | 超额处理 |
| --- | --- | --- |
| 文档数 | 10000 | 拒绝上传 |
| 存储空间 | 50 GB | 拒绝上传 |
| 每日检索次数 | 5000 | 限流 |
| LLM token/日 | 500000 | 降级或拒绝 |
| 并发会话 | 50 | 拒绝新会话 |

配额可按租户套餐调整，超额时返回明确错误码。

## 5. 数据安全

### 5.1 加密

- 每个租户可配置独立数据加密密钥（KEK）
- 密钥托管于 Vault，按租户隔离访问
- 跨租户数据导出需双管理员审批

### 5.2 审计

- 审计日志含 `tenant_id`，可按租户检索
- 租户管理员可查看本租户审计日志
- 跨租户操作（仅超管）单独高亮记录

## 6. 运维注意事项

### 6.1 跨租户运维操作

- 必须使用超管账户并记录操作原因
- 操作前后核对 `tenant_id` 上下文
- 高危操作（如批量删除）需双人确认

### 6.2 性能影响

- RLS 增加查询条件，需确保 `tenant_id` 有索引
- 大租户可能拖慢共享查询，必要时迁移到独立库
- 监控各租户资源占用，防止单租户影响整体

### 6.3 备份恢复

- 默认整库备份，恢复时影响所有租户
- 单租户恢复需从逻辑备份中抽取
- 关键租户建议额外独立备份

## 7. 租户生命周期

```
创建 -> 配置 -> 初始化数据 -> 运行 -> （扩容/缩容）-> 归档 -> 删除
```

- **创建**：分配 tenant_id、密钥、配额
- **归档**：导出数据后停用，保留 30 天
- **删除**：清理所有数据与密钥，不可恢复

## 8. 隔离验证测试

定期执行越权测试，验证 RLS 有效性：

```python
def test_cross_tenant_isolation(client, tenant_a_token, tenant_b_doc):
    resp = client.get(f"/api/v2/documents/{tenant_b_doc}",
                      headers={"Authorization": f"Bearer {tenant_a_token}"})
    assert resp.status_code == 404  # 不可见
```

## 9. 模型迁移

如需从 RLS 迁移到独立库（大客户场景）：

1. 创建租户独立实例
2. 按租户导出数据
3. 导入独立实例并验证
4. 切换路由，原库保留观察后清理

> RLS 是数据安全的最后一道防线，任何表结构变更都要同步检查 RLS 策略覆盖。
