# 插件开发指南

> EnterpriseKB 提供完善的插件机制，允许开发者在不修改核心代码的前提下扩展文档解析器、检索后处理、LLM 工具等能力。

## 1. 插件架构概述

插件系统基于「钩子（Hook）+ 注册中心」模式设计：

- **钩子点**：核心流程中预留的扩展位置
- **插件类**：实现特定接口的 Python 类
- **注册中心**：在启动时加载并管理插件生命周期

```
[请求] -> [前置钩子] -> [核心检索] -> [后置钩子] -> [响应]
                ^                          ^
            插件可拦截/改写输入        插件可改写/过滤输出
```

## 2. 支持的插件类型

| 类型 | 接口 | 触发时机 |
| --- | --- | --- |
| DocumentParser | 解析文档为结构化块 | 文档入库时 |
| QueryRewriter | 改写用户查询 | 检索前 |
| RetrieverFilter | 过滤检索结果 | 检索后、重排前 |
| Reranker | 自定义重排序 | 重排阶段 |
| ToolProvider | 为 LLM 提供工具调用 | 问答阶段 |
| ResponsePostProcessor | 改写最终回答 | 返回前 |

## 3. 接口定义

所有插件继承自 `BasePlugin`，并实现对应类型的抽象方法：

```python
from enterprise_kb.plugins import BasePlugin, QueryRewriter, PluginMeta

@PluginMeta(
    name="synonym-expander",
    version="1.0.0",
    type="query_rewriter",
    priority=10,
)
class SynonymExpander(BasePlugin, QueryRewriter):
    def __init__(self, config):
        self.synonyms = config.get("synonyms", {})

    def rewrite(self, query: str, context: dict) -> str:
        for src, dst in self.synonyms.items():
            query = query.replace(src, dst)
        return query
```

## 4. 注册流程

### 4.1 目录约定

将插件放置在 `backend/plugins/` 下，每个插件一个独立目录：

```
plugins/
└── synonym_expander/
    ├── __init__.py
    ├── plugin.py        # 插件实现
    ├── config.yaml      # 默认配置
    └── README.md
```

### 4.2 启用插件

在 `config/local.yaml` 中声明：

```yaml
plugins:
  enabled:
    - synonym_expander
  config:
    synonym_expander:
      synonyms:
        年假: 年休假
        报销: 费用报销
```

启动时框架会自动扫描 `plugins` 目录，加载 `@PluginMeta` 装饰的类并实例化。

## 5. 完整示例：自定义文档解析器

以下插件用于解析 `.eml` 邮件文件：

```python
import email
from enterprise_kb.plugins import BasePlugin, DocumentParser, PluginMeta

@PluginMeta(name="eml-parser", version="0.1.0", type="document_parser")
class EmlParser(BasePlugin, DocumentParser):
    supported_extensions = [".eml"]

    def parse(self, file_path: str) -> list[dict]:
        with open(file_path, "rb") as f:
            msg = email.message_from_binary_file(f)
        subject = msg.get("Subject", "")
        body = self._extract_body(msg)
        return [{
            "title": subject,
            "content": body,
            "metadata": {"source": "email", "from": msg.get("From")},
        }]

    def _extract_body(self, msg):
        if msg.is_multipart():
            for part in msg.walk():
                if part.get_content_type() == "text/plain":
                    return part.get_payload(decode=True).decode("utf-8", "ignore")
        return msg.get_payload(decode=True).decode("utf-8", "ignore")
```

## 6. 调试方法

### 6.1 单元测试

为插件编写独立测试，使用框架提供的测试夹具：

```python
from enterprise_kb.testing import PluginTestRunner

def test_synonym_expander():
    runner = PluginTestRunner("synonym-expander", {"synonyms": {"年假": "年休假"}})
    out = runner.invoke("rewrite", "年假怎么请")
    assert out == "年休假怎么请"
```

### 6.2 本地调试模式

```bash
ekb plugin debug synonym-expander --input "年假申请"
```

该命令会打印钩子调用链与耗时，方便定位问题。

## 7. 生命周期与错误处理

- `on_load()`：插件加载时调用，可读取配置、建立连接
- `on_unload()`：卸载时调用，释放资源
- 插件抛出异常会被框架捕获并记录日志，默认不影响主流程（可配置 `fail_fast: true` 改变行为）

## 8. 发布与分发

1. 在插件目录执行 `ekb plugin package`，生成 `.ekp` 包
2. 上传到内部插件市场
3. 其他实例通过 `ekb plugin install <name>` 安装

> 优先级数值越小越先执行；同类插件按 priority 升序排列。

## 9. 最佳实践

- 插件应保持无状态或使用外部存储持久化状态
- 耗时操作建议异步化，避免阻塞请求
- 对核心接口变更保持向后兼容
