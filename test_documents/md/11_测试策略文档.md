# 测试策略文档

> 本文档定义 EnterpriseKB 的测试分层、覆盖率要求、CI 集成与检索效果评测体系。

## 1. 测试目标

- 保证核心检索与问答链路稳定可靠
- 防止回归，支撑快速迭代
- 量化评估检索质量，指导模型与参数优化

## 2. 测试金字塔

```
        /\
       /  \       E2E 测试（少量，关键链路）
      /----\
     /      \     集成测试（接口、组件协作）
    /--------\
   /          \   单元测试（大量，快速）
  /____________\
```

| 层级 | 占比 | 工具 | 运行时长 |
| --- | --- | --- | --- |
| 单元测试 | 70% | pytest | <30s |
| 集成测试 | 20% | pytest + testcontainers | 2-5min |
| E2E 测试 | 10% | Playwright | 5-10min |

## 3. 单元测试

### 3.1 范围

- 核心算法：分块、融合、重排序逻辑
- 工具函数：文本清洗、token 计算
- 插件：每个插件独立测试

### 3.2 示例

```python
import pytest
from backend.core.fusion import rrf_fusion

def test_rrf_fusion_basic():
    vec_results = [("d1", 1), ("d2", 2), ("d3", 3)]
    kw_results = [("d2", 1), ("d4", 2)]
    fused = rrf_fusion(vec_results, kw_results, k=60)
    assert fused[0][0] == "d2"  # 两路都命中的应排前
```

## 4. 集成测试

### 4.1 接口测试

使用 testcontainers 启动真实 PostgreSQL + Redis：

```python
@pytest.fixture(scope="session")
def pg_container():
    with PostgresContainer("pgvector/pgvector:pg16") as pg:
        yield pg.get_connection_url()

def test_retrieve_endpoint(client, seeded_docs):
    resp = client.post("/api/v2/retrieve", json={"query": "年假", "top_k": 3})
    assert resp.status_code == 200
    assert len(resp.json()["data"]["items"]) <= 3
```

### 4.2 组件协作

- 文档上传 -> 解析 -> 向量化的完整链路
- 鉴权与多租户隔离验证

## 5. E2E 测试

使用 Playwright 模拟真实用户操作：

1. 登录系统
2. 上传一份文档
3. 等待索引完成
4. 发起提问并验证回答包含预期内容

## 6. 覆盖率要求

| 模块 | 行覆盖率 | 分支覆盖率 |
| --- | --- | --- |
| core（检索核心） | ≥90% | ≥85% |
| api | ≥80% | ≥75% |
| plugins | ≥75% | ≥70% |
| 整体 | ≥80% | - |

覆盖率通过 `pytest-cov` 采集，CI 中若低于阈值则构建失败。

## 7. 检索效果评测体系

### 7.1 评测集构建

- 维护 golden set：每个场景含查询、相关文档集合、期望答案要点
- 评测集按领域分类（HR / 财务 / IT / 行政）

### 7.2 评测指标

| 指标 | 含义 | 目标 |
| --- | --- | --- |
| Recall@5 | Top5 命中相关文档比例 | ≥0.85 |
| MRR | 平均倒数排名 | ≥0.70 |
| nDCG@5 | 归一化折损累计增益 | ≥0.75 |
| Answer Faithfulness | 回答与来源一致性 | ≥0.80 |

### 7.3 自动化评测脚本

```bash
ekb eval --dataset golden/hr_v3.jsonl --metrics recall,mrr,faithfulness
```

每次模型或参数变更必须跑评测，结果对比基线，若关键指标下降超 2% 需评审。

## 8. 性能与压力测试

- 使用 Locust 模拟并发检索
- 基准：100 并发下 P95 延迟 < 800ms
- 大数据量测试：百万级分块下的召回延迟

## 9. CI 集成

### 9.1 流水线阶段

1. Lint（ruff + mypy + 前端 lint）
2. 单元测试 + 覆盖率
3. 集成测试
4. 安全扫描（依赖漏洞 + SAST）
5. 构建镜像
6. E2E（仅 main 分支）

### 9.2 并行优化

- 单元测试按模块分片并行执行
- 测试结果缓存，仅运行受影响模块

## 10. 测试数据管理

- 测试夹具统一存放 `tests/fixtures/`
- 敏感数据使用脱敏样本
- 大文本测试数据按需生成，不提交仓库

## 11. 缺陷管理

- 测试发现的缺陷记录到 Issue，标注 `bug` 与优先级
- 修复后必须补充回归测试防止复发

> 评测集是质量的生命线，任何对评测集的修改需双人 Review。
