# 系统架构说明文档

> 本文档描述 EnterpriseKB 的整体架构、核心组件、数据流向与关键技术选型理由。

## 1. 架构总览

系统采用前后端分离 + 异步任务队列的分层架构，整体可分为四层：

```
┌─────────────────────────────────────────────┐
│  接入层  (Nginx / API Gateway)              │
├─────────────────────────────────────────────┤
│  应用层  (FastAPI API  +  Astro 前端)        │
├─────────────────────────────────────────────┤
│  能力层  (检索引擎 / LLM编排 / 插件系统)     │
├─────────────────────────────────────────────┤
│  数据层  (PostgreSQL+pgvector / Redis / OSS)│
└─────────────────────────────────────────────┘
```

## 2. 核心组件说明

### 2.1 API 网关

负责统一鉴权、限流、路由分发。基于 APISIX 实现，支持多租户路由与灰度发布。

### 2.2 应用服务

- **API 服务**：FastAPI 实现，处理同步请求（检索、问答、管理）
- **Worker 服务**：Celery 实现，处理异步任务（文档解析、向量化、索引构建）
- **前端**：Astro 静态站点 + Vue 交互组件，支持 SSR 与 Islands 架构

### 2.3 检索引擎

混合检索流水线：

1. 查询改写（同义扩展、HyDE 生成）
2. 向量召回（pgvector HNSW 索引）
3. 关键词召回（PostgreSQL 全文检索 / BM25）
4. 结果融合（RRF 倒数排名融合）
5. 重排序（Cross-Encoder 模型）

### 2.4 LLM 编排

基于 LangGraph 构建的有状态工作流，支持多步推理、工具调用与引用溯源。

### 2.5 数据存储

| 存储 | 用途 | 选型理由 |
| --- | --- | --- |
| PostgreSQL + pgvector | 业务数据 + 向量索引 | 事务一致性，避免多系统同步 |
| Redis | 缓存、会话、任务队列 | 高性能低延迟 |
| MinIO / S3 | 原始文档与附件 | 兼容 S3 协议，可平滑迁移 |
| Elasticsearch（可选） | 全文检索增强 | 大规模关键词检索场景 |

## 3. 数据流说明

### 3.1 文档入库流程

```
用户上传 -> API接收 -> 写入OSS -> 投递Worker任务
-> 解析为Chunk -> 调用Embedding -> 写入向量表
-> 更新文档状态为"已索引" -> 通知用户
```

### 3.2 问答检索流程

```
用户提问 -> 查询改写 -> 并行召回(向量+关键词)
-> RRF融合 -> 重排序 -> 取TopK
-> 构造Prompt -> 调用LLM -> 流式返回 + 引用
```

## 4. 技术选型理由

### 4.1 为什么选择 pgvector 而非独立向量库

- 减少运维组件数量
- 向量与业务数据在同一事务，保证一致性
- 中等规模（千万级向量）下性能足够，HNSW 索引支持亚秒级查询

### 4.2 为什么选择 Celery 而非轻量队列

- 文档解析是 CPU 密集型长任务，需要可靠重试与优先级队列
- Celery 生态成熟，监控（Flower）完善
- 与 Redis 复用，降低部署复杂度

### 4.3 为什么选择 LangGraph

- 需要多步推理与工具调用编排
- 显式状态图便于调试与可视化
- 支持人工审批节点，满足合规场景

## 5. 非功能性设计

### 5.1 高可用

- API 服务无状态，可水平扩缩
- 数据库主从复制 + 自动故障转移
- Redis Sentinel 哨兵模式

### 5.2 可扩展性

- 检索可通过分片（按租户/时间）水平扩展
- Embedding 调用支持批处理与并发限流
- 插件机制保证功能扩展不侵入核心

### 5.3 可观测性

- 结构化日志（JSON）统一收集到 ELK
- Prometheus 指标暴露，Grafana 可视化
- OpenTelemetry 全链路追踪，串联 API-Worker-DB

## 6. 多租户与隔离

采用「共享数据库 + 行级隔离（RLS）」模型，详见《多租户架构说明》。

## 7. 安全边界

- 所有外部访问经过网关鉴权
- 敏感配置通过 Vault 注入，不落盘明文
- 数据库连接走内网，最小权限账户

## 8. 演进路线

| 阶段 | 目标 |

| v2.x | 完善混合检索与插件生态 |
