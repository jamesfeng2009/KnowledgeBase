常见错误类型参考：
- `HTTP 429`: 限流触发（RateLimiter / RedisRateLimiter 拒绝）
- `HTTP 401`: 认证失败（JWT 过期 / 无效）
- `HTTP 403`: 权限不足（知识库访问被拒）
- `HTTP 500`: 内部服务器错误（LLM Provider 异常 / DB 超时等）
- `HTTP 503`: 数据库连接失败
- `SSE error 事件`: 流式过程中 LLM / 检索异常
- `SSE 流未正常结束`: 缺少 done 事件（超时 / 连接断开）
- `ConnectionError`: 网络连接异常
- `Timeout`: 请求超时（超过 SSE_MAX_DURATION=120s）

### 3.3 容量规划建议

#### 推荐配置（满足 SLA 目标）

| 并发用户规模 | API 实例数 | API 实例规格 | DB 规格 | Redis 规格 | 预估月成本 |

| 50-100 并发 | 3-4 | 4C8G | 8C16G | 4G | |
| 100+ 并发 | | | | | |

#### 扩展策略

1. **水平扩展（推荐）**：
   - 增加 API 实例数，通过负载均衡分发请求
   - 限流器需切换为 Redis-backed 模式（RedisRateLimiter）实现多实例共享计数
   - SSE 长连接场景需注意负载均衡器的连接超时配置（建议 > 120s）

2. **垂直扩展**：
   - 提升 API 实例 CPU/内存规格
   - 提升 DB 连接池大小（当前配置：__）
   - 注意 SSE 长连接期间不持有 DB 连接（已在 chat.py 中 commit+close）

3. **缓存优化**：
   - 启用答案缓存（cache_scope 指纹隔离）
   - 对高频事实型问题启用 FAQ Matcher 短路

4. **LLM 成本优化**：
   - 简单事实型问题路由到轻量模型（qwen-turbo / claude-haiku-4）
   - 复杂推理型问题使用旗舰模型（claude-sonnet-4.6 / qwen-max）
   - 自部署 vLLM 模型（llama-3.3-70b / qwen3-72b）降低 API 调用成本

#### 预警阈值建议

| 指标 | 告警阈值 | 紧急阈值 | 建议动作 |
|------|---------|---------|---------|
| P95 延迟 | > 5000 ms | > 10000 ms | 检查 LLM 延迟 / 增加实例 |
| 错误率 | > 2% | > 5% | 检查熔断器状态 / DB 连接 |
| API CPU | > 70% | > 90% | 水平扩展 |
| DB CPU | > 60% | > 85% | 优化慢查询 / 垂直扩展 |
| 熔断器状态 | 任意 OPEN | 多个 OPEN | 检查 LLM Provider 可用性 |

### 5.2 SSE 事件类型参考

> 与后端 `app/utils/sse.py` 的 `SSEEventType` 对齐：

| 事件类型 | 说明 | 压测关注点 |
|---------|------|-----------|
| `meta` | 对话元数据（conversation_id, agent_type） | - |
| `thinking` | Agent 思考进度 | 影响首 token 延迟 |
| `retrieve_start` / `retrieve_end` | 检索进度 | 检索耗时 |
| `tool_call_start` / `tool_call_end` | 工具调用进度 | 工具调用耗时 |
| 默认（data） | 逐 token 文本片段 | TTFT / 流式速度 |
| `sources` | 引用来源 | 检索质量 |
| `quality` | 质量评分 | 答案质量 |
| `done` | 流结束标记（token_count, model_used） | 完整延迟 / Token 成本 |
| `error` | 错误事件 | 错误分析 |
