SECTION 01

架构设计：三项扩展整体架构

三项扩展并非孤立，而是共同重塑 Agent Loop 的工具调用决策链。核心思路是将原本单一的 beforeTool 守卫 → 执行 升级为五阶段决策链：beforeTool（安全检查）→ 循环检测 → RBAC（角色检查）→ 参数级（参数检查）→ 执行 → afterTool（审计）。循环检测在安全检查之后、真正执行之前拦截无效重复；并行调度在执行阶段对只读工具并发；动态授权则贯穿 beforeTool/RBAC/参数级/afterTool 四层。

SECTION 03

详细设计：循环检测

循环检测扩展解决 Agent Loop 中"LLM 反复调用同一工具相同参数却不前进"的死循环问题。现有防无限循环仅靠 max_iterations=5 计数，无法区分"5 次有效迭代"与"5 次原地打转"。本扩展在工具调用层引入细粒度循环检测，超阈值时返回结构化错误引导 LLM 更换策略。

工具调用记录

from dataclasses import dataclass, field
from typing import Any
import hashlib, json, time

@dataclass
class ToolCallRecord:
    """单次工具调用记录 — 循环检测的基础数据单元。"""
    tool_name: str
    arguments: dict[str, Any]
    tool_use_id: str
    iteration: int
    timestamp: float = field(default_factory=time.time)

    @property
    def signature(self) -> str:
        """调用签名 — 工具名 + 规范化参数的哈希，用于重复检测。"""
        # 规范化：按 key 排序后 JSON 序列化，确保参数顺序不影响比对
        canonical = json.dumps(
            {"tool": self.tool_name, "args": self.arguments},
            sort_keys=True, ensure_ascii=False,
        )
        return hashlib.sha256(canonical.encode()).hexdigest()[:16]

    @property
    def tool_only_key(self) -> str:
        """仅工具名键 — 用于调用图环路检测（A→B→A）。"""
        return self.tool_name

3.2 检测算法 算法

检测 1：连续重复调用

追踪最近 N 次调用的签名，若同一签名连续出现 ≥ 阈值次（默认 2 次），判定为无效循环。

def _detect_consecutive_duplicate(self, record: ToolCallRecord) -> LoopViolation | None:
    """检测连续重复调用 — 同一工具+相同参数连续出现 ≥ 阈值次。"""
    sig = record.signature
    recent = self._history[-self._window_size:]  # 滑动窗口

    # 统计窗口内同签名连续出现次数
    consecutive = 0
    for past in reversed(recent):
        if past.signature == sig:
            consecutive += 1
        else:
            break  # 遇到不同签名即中断连续性

    if consecutive >= self._max_consecutive:
        return LoopViolation(
            violation_type="consecutive_duplicate",
            tool_name=record.tool_name,
            count=consecutive,
            message=f"工具 {record.tool_name} 以相同参数连续调用 {consecutive} 次，疑似死循环",
            suggestion="请更换工具、调整参数或直接生成答案",
        )
    return None

检测 2：工具调用图环路

构建工具调用有向图（A→B 表示 B 紧随 A 被调用），用 DFS 检测环。识别 A→B→A 模式（长度 ≤ 阈值的环）。

def _detect_cycle(self, record: ToolCallRecord) -> LoopViolation | None:
    """检测工具调用图中的环 — 如 A→B→A 模式。"""
    if len(self._history) < 2:
        return None

    # 构建最近 K 次调用的工具名序列
    sequence = [r.tool_only_key for r in self._history[-self._cycle_window:]] + [record.tool_only_key]

    # 检测序列末尾是否存在回文环（A...A 模式）
    # 检查长度 2~max_cycle_length 的环
    for cycle_len in range(2, self._max_cycle_length + 1):
        if len(sequence) >= cycle_len * 2:
            # 比较 [末尾 cycle_len 个] 与 [其前 cycle_len 个]
            tail = sequence[-cycle_len:]
            prev = sequence[-cycle_len * 2:-cycle_len]
            if tail == prev:
                return LoopViolation(
                    violation_type="call_cycle",
                    tool_name=record.tool_name,
                    count=cycle_len,
                    message=f"检测到工具调用环 {'→'.join(tail)}→{'→'.join(tail)}，长度 {cycle_len}",
                    suggestion="检测到循环调用模式，请尝试不同工具或直接生成答案",
                )
    return None

检测 3：合法重试区分

关键设计：区分合法重试与无效循环。以下情况即使工具名相同也不视为循环：

  • 参数不同：分页查询 offset 不同、查询关键词不同 → 签名不同，自然不触发
  • 工具结果为错误：上次调用返回 error，LLM 调整参数重试 → 标记 is_retry_after_error=True 放行
  • 显式重试标记：LLM 在 tool_use input 中带 "_retry": true → 跳过连续检测

SECTION 04

详细设计：并行工具调用

4.3 并行执行核心逻辑 实现

import asyncio
from typing import Any

class ToolScheduler:
    """并行工具调度器 — 只读并发、写串行。"""

    def __init__(self, engine: "AgenticRAGEngine") -> None:
        self._engine = engine

    async def schedule(self, state: AgentState, tool_uses: list[ToolUse]) -> list[dict]:
        """调度执行一批 tool_use，返回按 tool_use_id 合并的结果列表。"""
        if not tool_uses:
            return []

        # 1. 按只读/写分类
        read_tools: list[ToolUse] = []
        write_tools: list[ToolUse] = []
        for tu in tool_uses:
            if self._engine._tool_guard.is_readonly(tu["name"]):
                read_tools.append(tu)
            else:
                write_tools.append(tu)

        results: list[dict[str, dict]] = []

        # 2. 只读组 — asyncio.gather 并发执行守卫链
        if read_tools:
            read_results = await asyncio.gather(
                *(self._engine._execute_tool_use(state, tu) for tu in read_tools),
                return_exceptions=True,  # 单个失败不中断其他
            )
            for tu, res in zip(read_tools, read_results):
                results.append(self._wrap_result(tu, res))

        # 3. 写组 — 严格串行执行（避免竞态）
        for tu in write_tools:
            try:
                await self._engine._execute_tool_use(state, tu)
                results.append({"tool_use_id": tu["id"], "status": "ok"})
            except Exception as exc:
                results.append(self._wrap_error(tu, exc))

        # 4. 按 LLM 返回顺序（tool_use_id）合并
        id_order = {tu["id"]: idx for idx, tu in enumerate(tool_uses)}
        results.sort(key=lambda r: id_order.get(r.get("tool_use_id"), len(tool_uses)))
        return results

    @staticmethod
    def _wrap_result(tu: ToolUse, res: Any) -> dict:
        """包装 gather 结果（可能是异常）。"""
        if isinstance(res, Exception):
            return {"tool_use_id": tu["id"], "tool": tu["name"],
                    "status": "error", "error": str(res)}
        return {"tool_use_id": tu["id"], "tool": tu["name"], "status": "ok"}

4.4 错误处理与结果合并 容错

并发错误隔离

  • return_exceptions=True 防止单个只读工具失败中断整组
  • 每个工具结果独立带 status: ok/error
  • 异常被包装为结构化错误写入 tool_results

结果顺序保证

  • 用 tool_use_id 建立 LLM 返回顺序索引
  • 并发完成后按原始顺序排序合并
  • 确保 LLM 收到的 tool_result 顺序与请求对应

    messages = [
        {"role": "system", "content": "根据用户问题选择合适的工具调用..."},
        {"role": "user", "content": state["query"]},
    ]

    # ① 先收集本轮全部 tool_use（不立即执行）
    collected: list[ToolUse] = []
    async for chunk in self.llm.chat(messages, tools=tools, stream=False):
        if isinstance(chunk, dict) and chunk.get("type") == "tool_use":
            collected.append(chunk)

    if not collected:
        return

    # ② 委托 ToolScheduler 并行调度
    await self._tool_scheduler.schedule(state, collected)

from enum import Enum
from dataclasses import dataclass

class AuthzDecision(Enum):
    """授权决策结果。"""
    ALLOW = "allow"
    DENY = "deny"

@dataclass
class AuthzResult:
    decision: AuthzDecision
    reason: str = ""
    required_role: str = ""
    actual_role: str = ""

    @property
    def allowed(self) -> bool:
        return self.decision == AuthzDecision.ALLOW

# 角色 → 允许调用的工具集合（配置驱动，支持环境变量覆盖）
_DEFAULT_ROLE_MATRIX: dict[str, set[str]] = {
    "viewer": {"knowledge_search", "document_get", "query_oa_approval"},
    "editor": {"knowledge_search", "document_get", "query_oa_approval", "document_create"},
    "kb_admin": {"knowledge_search", "document_get", "query_oa_approval", "document_create", "create_it_ticket"},
    "admin": {"*"},  # 全部工具
}

class RBACAuthorizer:
    """RBAC 角色授权器 — 基于角色矩阵判定工具调用权限。"""

    def __init__(self, role_matrix: dict[str, set[str]] | None = None) -> None:
        self._matrix = role_matrix or _DEFAULT_ROLE_MATRIX

    def check(self, role: str, tool_name: str) -> AuthzResult:
        """检查角色是否有权调用工具。"""
        allowed_tools = self._matrix.get(role, set())
        if "*" in allowed_tools or tool_name in allowed_tools:
            return AuthzResult(decision=AuthzDecision.ALLOW, reason="角色权限匹配",
                             actual_role=role)
        # 推断所需最低角色
        required = self._find_min_role(tool_name)
        return AuthzResult(
            decision=AuthzDecision.DENY,
            reason=f"角色 {role} 无权调用 {tool_name}",
            required_role=required, actual_role=role,
        )

    def _find_min_role(self, tool_name: str) -> str:
        """找到能调用该工具的最低权限角色。"""
        for role in ["viewer", "editor", "kb_admin", "admin"]:
            if tool_name in self._matrix.get(role, set()) or "*" in self._matrix.get(role, set):
                return role
        return "admin"

5.3 参数级授权规则引擎 新增

参数级授权在 RBAC 通过后，对工具入参做字段级约束。典型场景：document_create 对 editor 角色限制只能创建 status=draft 的文档，防止越权发布。

from enum import Enum
import re

class ParamOperator(Enum):
    """参数约束操作符。"""
    EQ = "eq"          # 等于
    IN = "in"          # 属于集合
    REGEX = "regex"      # 正则匹配
    NOT_IN = "not_in"    # 不属于集合
    RANGE = "range"      # 数值范围 [min, max]

@dataclass
class ParamRule:
    """单条参数约束规则。"""
    tool_name: str
    field: str                    # 参数字段名
    operator: ParamOperator
    value: Any                    # 约束值（集合/正则/范围）
    roles: set[str]               # 规则适用的角色集合
    message: str = ""             # 违规提示

# 默认参数级规则配置
_DEFAULT_PARAM_RULES: list[ParamRule] = [
    ParamRule(
        tool_name="document_create",
        field="status",
        operator=ParamOperator.EQ,
        value="draft",
        roles={"editor"},  # 仅 editor 受此约束，admin/kb_admin 不受限
        message="editor 角色只能创建 draft 状态文档",
    ),
    ParamRule(
        tool_name="create_it_ticket",
        field="priority",
        operator=ParamOperator.NOT_IN,
        value={"urgent"},
        roles={"kb_admin", "editor"},
        message="仅 admin 可创建 urgent 优先级工单",
    ),
    ParamRule(
        tool_name="knowledge_search",
        field="query",
        operator=ParamOperator.REGEX,
        value=r"^.{1,500}$",  # 查询长度限制
        roles={"*"},
        message="查询关键词长度需在 1-500 字符",
    ),
]

class ParamAuthorizer:
    """参数级授权规则引擎。"""

    def __init__(self, rules: list[ParamRule] | None = None) -> None:
        self._rules = rules or _DEFAULT_PARAM_RULES

    def check(self, tool_name: str, arguments: dict, role: str) -> AuthzResult:
        """检查工具参数是否符合角色约束规则。"""
        for rule in self._rules:
            if rule.tool_name != tool_name:
                continue
            if "*" not in rule.roles and role not in rule.roles:
                continue  # 规则不适用于当前角色
            if rule.field not in arguments:
                continue  # 参数未提供，跳过（由工具自身校验必填）

            val = arguments[rule.field]
            if not self._match(val, rule.operator, rule.value):
                return AuthzResult(
                    decision=AuthzDecision.DENY,
                    reason=f"参数违规: {rule.message}",
                    actual_role=role,
                )
        return AuthzResult(decision=AuthzDecision.ALLOW, reason="参数合规", actual_role=role)

    @staticmethod
    def _match(val: Any, op: ParamOperator, expected: Any) -> bool:
        """执行单条规则匹配。"""
        if op == ParamOperator.EQ:
            return val == expected
        if op == ParamOperator.IN:
            return val in expected
        if op == ParamOperator.NOT_IN:
            return val not in expected
        if op == ParamOperator.REGEX:
            return bool(re.match(expected, str(val)))
        if op == ParamOperator.RANGE:
            return expected[0] <= val <= expected[1]
        return True

async def _execute_tool_use(self, state: AgentState, tool_use: ToolUse) -> None:
    tool_name = tool_use.get("name", "")
    tool_input = tool_use.get("input", {})
    tool_use_id = tool_use.get("id", "")
    user_role = state.get("user_role", "viewer")

    ctx = ToolExecutionContext(
        tool_name=tool_name, tool_input=tool_input, tool_use_id=tool_use_id,
        user_id=state.get("user_id", ""), user_role=user_role,
        session_id=state.get("session_id", ""),
        iteration=state.get("iteration", 0), start_time=time.time(),
    )

    # ① beforeTool — 现有 DangerousToolGuard（保持不变）
    guard_result = self._tool_guard.check(tool_name, tool_input)
    if guard_result.needs_confirmation:
        await self._record_blocked(state, ctx, tool_name, tool_input, guard_result.reason)
        return

    # ② 循环检测 — 扩展 1 新增
    if self._loop_detector is not None:
        record = ToolCallRecord(tool_name, tool_input, tool_use_id, ctx.iteration)
        violation = self._loop_detector.check_before_execute(record)
        if violation is not None:
            await self._record_violation(state, ctx, violation)
            return

    # ③ RBAC — 扩展 3 新增
    if self._rbac_authorizer is not None:
        rbac_result = self._rbac_authorizer.check(user_role, tool_name)
        if not rbac_result.allowed:
            await self._record_denied(state, ctx, rbac_result)
            return

    # ④ 参数级 — 扩展 3 新增
    if self._param_authorizer is not None:
        param_result = self._param_authorizer.check(tool_name, tool_input, user_role)
        if not param_result.allowed:
            await self._record_denied(state, ctx, param_result)
            return

    # ⑤ 执行 — 现有 MCP 调用（保持不变）
    try:
        result = await self.mcp.call_tool(tool_name, tool_input)
        state["tool_results"].append({"tool": tool_name, "arguments": tool_input, "result": result, "content": result})
        outcome = ToolExecutionOutcome(success=True, result=result, duration_ms=(time.time()-ctx.start_time)*1000, result_summary=self._summarize(result))
        if self._loop_detector is not None:
            self._loop_detector.record_call(ToolCallRecord(tool_name, tool_input, tool_use_id, ctx.iteration))
    except Exception as exc:
        outcome = ToolExecutionOutcome(success=False, error=exc, duration_ms=(time.time()-ctx.start_time)*1000)
        state["tool_results"].append({"tool": tool_name, "arguments": tool_input, "result": str(exc), "content": str(exc)})

    # ⑥ afterTool — 扩展 3 新增
    if self._after_tool_hook is not None:
        try:
            await self._after_tool_hook.after_tool(ctx, outcome)
        except Exception as hook_exc:
            log.warning("engine.after_tool_hook_error", error=str(hook_exc))

SECTION 10

风险分析：潜在风险与缓解

识别三项扩展在性能、安全、正确性、兼容性四个维度的潜在风险，并给出针对性缓解措施。所有风险均控制在"不阻断主流程"范围内——扩展组件异常时降级为原有行为。

10.1 风险矩阵 风险

R1: 循环误判阻断合法调用 中

分页查询、错误重试等合法场景被循环检测误判为死循环，导致 Agent 无法获取数据。

缓解：① 签名包含规范化参数，参数不同即不触发；② is_retry_after_error 标记放行错误重试；③ enabled=False 可全局关闭；④ 单元测试覆盖分页/重试场景。

R2: 并行调用引发资源竞争 中

多个只读工具并发访问数据库，连接池耗尽或触发限流。

缓解：① max_concurrency=5 限制并发上限；② 只读工具无写副作用，竞态风险低；③ 数据库连接池配置独立监控；④ 异常隔离不扩散。

R3: RBAC 角色配置错误锁死 高

角色矩阵配置过严，导致所有用户无法调用工具，Agent 功能瘫痪。

缓解：① admin 角色通配 "*" 兜底；② 配置热加载，无需重启；③ rbac_authorizer=None 可完全禁用回退；④ 上线前在测试环境验证全角色矩阵。

R4: afterTool 审计拖慢主流程 低

审计日志持久化（写库）增加每次工具调用延迟。

缓解：① afterTool 异常不阻断主流程（try/except 包裹）；② 审计写入可改为 Celery 异步任务；③ after_tool_hook=None 可禁用；④ 仅记录摘要不记全量参数。

R5: 并行结果顺序错乱 低

asyncio.gather 并发完成后结果顺序与 LLM 期望不一致，导致 LLM 困惑。

缓解：① 用 tool_use_id 建立顺序索引，合并后按原序排序；② 测试用例验证顺序保证；③ zip(gather) 保留输入顺序对应关系。

R6: 守卫链阶段间状态泄漏 中

某阶段拒绝后未正确返回，后续阶段仍执行，导致越权调用。

缓解：① 每阶段拒绝后 return 提前退出；② 集成测试验证拒绝路径不调用 MCP；③ 阶段间无共享可变状态。

R7: 向后兼容性破坏 高

engine.py 改造导致现有 762 项测试回归。

缓解：① 所有扩展参数默认 None，回退原逻辑；② 现有 test_tool_guard/test_rag_engine 不改；③ CI 全量回归门禁；④ 分阶段合并，每阶段独立验证。

R8: 参数规则配置膨胀 低

随工具增多，参数规则配置复杂度上升，维护困难。

缓解：① 规则配置外置 YAML 文件；② get_rules_for_tool 支持调试查询；③ 规则按工具名索引，查找 O(1)；④ 文档化每个规则的业务含义。

R9: 循环检测内存增长 低

tool_call_history 无限增长，长会话内存溢出。

缓解：① max_total_calls=15 兜底限制；② 滑动窗口 window_size=5 仅保留近期；③ reset() 在新会话时清空；④ 历史仅存签名哈希不存全量参数。
