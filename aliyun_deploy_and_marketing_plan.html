P0 阻塞部署（必须修复）

1. 数据库表初始化机制完全缺失 头号阻塞

文件：app/main.py:30-36（lifespan 仅配置日志）、app/database.py（仅创建 engine/session）

问题：alembic>=1.14.0 已在 requirements.txt 声明，但全项目无 alembic.ini、无 migrations/ 目录。Base.metadata.create_all 仅出现在 tests/conftest.py，生产代码从不调用。

后果：部署到阿里云全新 PostgreSQL 后，uvicorn 能启动、/health 能通过，但任何触及数据库的 API 调用都会 500 报 "relation does not exist"。

修复方向（三选一）：

  1. 补 alembic init + 首版 migration（推荐生产环境）
  2. 在 lifespan 中调用 Base.metadata.create_all（demo 快速方案）
  3. 提供 scripts/init_db.py 初始化脚本

2. docker-compose 健康检查与依赖不完整

文件问题
docker-compose.yml L56-59core-engine healthcheck 仅 curl /health，该端点不触 DB，表缺失时仍报 healthy
docker-compose.yml L29-36minio 服务无 healthcheck
docker-compose.yml L127-156milvus-etcd、milvus-minio 无 healthcheck，milvus depends_on 无 condition
docker-compose.yml L83-110celery-worker/beat 不等待 schema 就绪

P2 仅占位无害（无需修改）

以下均为正常设计，无需修改即可部署：

  • NotImplementedError 全部为抽象基类方法（由子类实现）
  • vLLM/VLM 的 api_key="dummy" 是 vLLM 本地部署标准用法
  • LDAP 同步服务已完整实现（ldap3 真实连接，仅 LDAP_URL 为空时静默返回）
  • CrewAI 多 Agent 协作已实现，降级处理得当
  • 前端 18 个页面的 mockXxx() 是 API 失败时的 fallback，非主路径
  • 各处 pass 语句均为合法的异常吞咽/最佳努力清理
